# Trading-Analysis

Учебный проект для сбора и анализа дневных свечей MOEX. Совмещает Java-бэкенд (надёжный сбор данных) и Python-аналитику (статистика, индикаторы, модель), с целью прокачать инженерные навыки и позже вывести систему в облако.

> Статус: в разработке. Аналитика — исследовательская, **не торговая рекомендация**.

## Архитектура

```
MOEX API → Java collector → PostgreSQL → Python analysis → Java Telegram bot → Telegram
                                         └────────────────→ Desktop UI (PyQt)
```

| Компонент | Технологии | Задача |
|---|---|---|
| **Java collector** | Spring Boot, `MoexDataService`, `DataCollectionScheduler` | Забирает дневные свечи с MOEX, проверяет их и пишет в БД |
| **PostgreSQL** | Flyway (миграции) | Хранит свечи и справочник инструментов |
| **Python analysis** | pandas, statsmodels, scikit-learn/XGBoost | Считает индикаторы, статистику, обучает и оценивает модель |
| **Telegram bot** | Spring Boot | Принимает защищённые сигналы от Python и отправляет их в настроенный чат |
| **Desktop UI** | PyQt | Локальный просмотр графиков, индикаторов и результатов модели |

Каждый компонент решает одну задачу и не дублирует логику других: индикаторы считаются в одном месте и используются и в UI, и при обучении модели.

## Как запустить локально

> ⚠️ Раздел временный — уточнить и проверить перед коммитом. Ниже — предполагаемый минимум.

**Требования:** Java 17+, PostgreSQL 14+, Python 3.10+, Maven.

```bash
# 1. Поднять БД
docker-compose up -d postgres

# 2. Собрать и запустить Java-сборщик
cd java-collector
./mvnw spring-boot:run

# 3. Установить зависимости Python-модуля
cd ../python-analytics
pip install -r requirements.txt

# 4. Запустить desktop-приложение
python main.py
```

Секреты (пароль БД, при необходимости — токен MOEX) передаются через переменные окружения, не хранятся в репозитории.

Чтобы вручную рассчитать исследовательский сигнал для последней **закрытой** дневной свечи:

```bash
cd python-analytics
python src/run_analysis.py SBER --as-of 2026-10-30
# Или для всех активных бумаг из таблицы securities:
python src/run_analysis.py --all-active --as-of 2026-10-30
```

Для подключения к PostgreSQL используются `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` и `DB_PASSWORD`. CLI выводит JSON с сигналом и метриками walk-forward. Если получен `BUY_CANDIDATE`, он отправляется в Telegram через Java-бот; `NO_SIGNAL` не рассылается. `--no-notify` отключает отправку. Анализ следует запускать после того, как Java-сборщик записал завершённую свечу.

### Telegram-уведомления

1. Создай `.env` в корне репозитория по образцу [.env.example](./.env.example). Укажи токен бота, chat ID и длинный случайный `ANALYTICS_API_TOKEN` (одинаковый токен передаётся Python-клиентом и проверяется ботом). `.env` исключён из Git.
2. Запусти PostgreSQL, сборщик и бота: `docker compose up -d postgres collector telegram-bot`.
3. После сбора дневных данных запусти анализ, например: `docker compose run --rm analytics python run_analysis.py SBER --as-of 2026-10-30`.

Сейчас отправка происходит при запуске анализа, автоматического расписания анализа ещё нет. Ранее токен Telegram находился в локальном файле конфигурации; **отзови его через BotFather и создай новый**, затем сохрани новый токен только в `.env`.

## Данные и целевая переменная модели

- Таргет первого сигнала — положительная доходность `close-to-close` через 15 торговых свечей; комиссии и проскальзывание пока не учитываются.
- Обучающая выборка **не должна** включать последние `h` строк, для которых ещё неизвестен результат в будущем — иначе таргет ошибочно помечается как отрицательный.
- Валидация — последовательное разбиение по времени, с защитным промежутком (embargo) перед тестовым периодом, чтобы исключить утечку через пересекающиеся горизонты.
- Walk-forward сравнивает XGBoost с baseline по самому частому классу обучающего фолда; выводятся accuracy, balanced accuracy, precision, recall и Brier score.

## Дорожная карта

1. **Стабилизация локально** — починить баг с таргетом, единый модуль индикаторов, надёжный Java-сборщик, статистический профиль данных.
2. **Docker для разработки** — PostgreSQL + Java-сборщик в Compose; Python-анализ в headless-режиме (без PyQt) для последующей контейнеризации.
3. **CI/CD** — отдельные workflow для Java (сборка + тесты), Python (зависимости + pytest), Docker (build на PR, publish после мержа).
4. **Перенос вычислений на удалённый сервер** — сборщик, БД и headless-анализ переезжают на VPS; desktop-приложение остаётся локальным клиентом.
5. **Развитие Telegram-бота** — управление подписками на тикеры, расписание анализа и доставка сигналов по подпискам.
